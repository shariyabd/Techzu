# T00 — Bootstrap: starter kit, packages, tooling, CI and app shell

**Objective:** Scaffold the Laravel 13 Vue starter kit (`laravel/vue-starter-kit:dev-main`) with the global-constraint packages, Laravel Boost, Sail and two `.env` profiles, MySQL-backed Pest + Larastan + Pint + CI, and the shared app shell that every later task plugs into (route auto-loading, domain-exception rendering, Sanctum token API, throttling, lazy-loading guard, Inertia shared props, layout and navigation registry).

- **Depends on:** nothing
- **Wave:** 0
- **TDs implemented:** TD-001 (folder layout, thin controllers), TD-002 (Vue starter kit), TD-003 (Sanctum `/api/v1`, `{message, code}` errors), TD-005 (Sail + Local profiles), TD-010 (spatie/permission installed, `HasRoles`), TD-030 (Pest 4, Larastan 6, Pint), TD-031 (MySQL `techzu_testing`), TD-032 (`tests/Concurrency` suite), TD-033 (Scramble installed), TD-034 (CI), TD-101 (`preventLazyLoading`), TD-110 (abstract `DomainException` + single renderer), TD-120 (throttling, token abilities, whitelisted Inertia props), TD-130 (`env()` only in config), TD-140 (per-feature route files)

## Interfaces

**Consumes:** nothing (greenfield).

**Produces** (README §3, exact names)
```php
// app/Exceptions/Domain/DomainException.php  (§3.2)
abstract class DomainException extends \RuntimeException {
    abstract public function status(): int;        // HTTP status
    abstract public function errorCode(): string;  // stable snake_case code
}
```
- **Renderer** (`bootstrap/app.php`, §3.2): `expectsJson()` → `{"message": ..., "code": ...}` with `status()`; otherwise `back()->with('error', $message)`. Domain exceptions are not reported to the log (`dontReport`). Every `/api/*` request is forced to `Accept: application/json` by `ForceJsonResponse` (prepended to the `api` group), so API callers always get JSON.
- **Routing** (§3.10): `routes/web.php`, then every `routes/web/*.php` (alphabetical), inside `web`; every `routes/api/v1/*.php` with prefix `api/v1`, name prefix `api.v1.`, middleware `api` (which includes `throttle:api`). Each API file applies `auth:sanctum` itself, except `auth.php`.
- **API routes** (§3.10): `api.v1.auth.tokens.store` (POST `api/v1/auth/tokens`, `throttle:5,1`), `api.v1.auth.tokens.destroy` (DELETE `api/v1/auth/tokens/current`, `auth:sanctum`), `api.v1.auth.me` (GET `api/v1/me`, `auth:sanctum`).
  - `POST auth/tokens` body `{email, password, device_name}` → `201 {"data": {"token", "token_type": "Bearer", "abilities": [<permission names>]}}`; bad credentials → `422` with `errors.email`.
  - `DELETE auth/tokens/current` → `204`; the token row is deleted.
  - `GET me` → `200 {"data": {"id", "name", "email", "roles": [], "permissions": []}}`.
- **Home** (`routes/web.php`): `GET /` named `home` → `HomeController`. A guest goes to `login`. A user passing Gate `viewDashboard` goes to `dashboard`; anyone else goes to `tickets.index`. Both checks are guarded (`Gate::has('viewDashboard')`, `Route::has('tickets.index')`), so the route works before T04 and T05 merge; until then everyone lands on the `dashboard` placeholder. Fortify's `home` (the post-login, registration and verification redirect) is `/`.
- **Rate limiters** (`AppServiceProvider`): `api` = 60/min per user id or IP; `uploads` = 20/min per user id or IP (for T07's upload routes: `throttle:uploads`).
- **Lazy loading:** `Model::preventLazyLoading(! app()->isProduction())`.
- **Inertia shared props** (§3.13): `auth.user{id,name,email,email_verified_at,roles[]}` (null for guests), `auth.can{viewDashboard, manageImports, manageUsers, manageCategories, manageHolidays, createOnBehalf}` (all `false` placeholders, T04 replaces them), `flash{success,error}`, `notifications.unread_count` (closure returning `0`, T10 replaces the closure), plus the starter kit's `name` and `sidebarOpen`.
- **Frontend** (§3.13):
  - `resources/js/types/shared.ts` exports `SharedProps`, `AuthUser`, `AuthCan`. `SharedProps` is the **one** declaration of the shared props: `resources/js/types/global.d.ts` registers it as Inertia 3's `InertiaConfig.sharedPageProps`, so `usePage()` is typed without a generic (and `usePage<SharedProps>()` still compiles). `AuthUser` is the kit's `User` from `types/auth.ts`, reshaped to `{id, name, email, roles}`; `auth.user` is typed non-null as in the kit (only guest pages see `null`, and they only test it for truthiness).
  - `resources/js/config/navigation.ts` defines and exports `type NavItem = { title: string; href: string; icon?: Component; order: number; visible: (page: SharedProps) => boolean }`, plus `navItems` and `navigationFor(props: SharedProps): NavItem[]`, built from `import.meta.glob('./navigation/*.ts', { eager: true })`. Each module default-exports `NavItem[]`. Features import `NavItem` from `@/config/navigation`, add `resources/js/config/navigation/<feature>.ts` and never edit `navigation.ts`. The kit's `resources/js/types/navigation.ts` keeps `BreadcrumbItem` (still imported from `@/types`) and the kit's own link type, which is also named `NavItem` but is a different shape; feature code never imports `NavItem` from `@/types`.
  - `resources/js/layouts/AppLayout.vue` is the default layout that the kit's `app.ts` applies to every non-auth page (Inertia 3 `layout` option). It keeps the kit's `breadcrumbs` prop, which pages set as layout props (`defineOptions({ layout: { breadcrumbs } })` or `setLayoutProps()`); pages never wrap themselves in it. It renders the flash banner, and its sidebar renders `navigationFor(page.props)`.
- **Test infrastructure:** PHPUnit suites `Unit`, `Feature`, `Concurrency` (`tests/Concurrency`, configured with `DatabaseTruncation` by T01) and `Database`. Pest 4 on PHPUnit 12; `tests/Pest.php` binds `Tests\TestCase` + `RefreshDatabase` to `Feature` (T01 replaces it). The kit's tests stay PHPUnit classes. Tests run on MySQL `techzu_testing`.
- **Console:** `routes/console.php` holds no commands or schedules (T09 adds the `sla:scan` line).

use Database\Factories\UserFactory;
use Illuminate\Contracts\Auth\MustVerifyEmail;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Foundation\Auth\User as Authenticatable;
use Illuminate\Notifications\Notifiable;
use Illuminate\Support\Carbon;
use Laravel\Fortify\Contracts\PasskeyUser;
use Laravel\Fortify\PasskeyAuthenticatable;
use Laravel\Fortify\TwoFactorAuthenticatable;
use Laravel\Sanctum\HasApiTokens;
use Laravel\Sanctum\PersonalAccessToken;
use Laravel\Sanctum\TransientToken;
use Spatie\Permission\Traits\HasRoles;

/**
 * @property int $id
 * @property string $name
 * @property string $email
 * @property Carbon|null $email_verified_at
 * @property string $password
 * @property string|null $two_factor_secret
 * @property string|null $two_factor_recovery_codes
 * @property Carbon|null $two_factor_confirmed_at
 * @property string|null $remember_token
 * @property Carbon|null $created_at
 * @property Carbon|null $updated_at
 */
class User extends Authenticatable implements MustVerifyEmail, PasskeyUser
{
    // Session-authenticated requests carry a TransientToken, API requests a PersonalAccessToken.
    /** @use HasApiTokens<PersonalAccessToken|TransientToken> */
    use HasApiTokens;

    /** @use HasFactory<UserFactory> */
    use HasFactory, HasRoles, Notifiable, PasskeyAuthenticatable, TwoFactorAuthenticatable;

    /** @var list<string> */

        'name',
        'email',
        'password',
    ];

    /** @var list<string> */
    protected $hidden = [
        'password',
        'two_factor_secret',
        'two_factor_recovery_codes',
        'remember_token',
    ];

    /** @return array<string, string> */
    protected function casts(): array

            glob(__DIR__.'/../routes/web/*.php') ?: [],

        commands: __DIR__.'/../routes/console.php',
        health: '/up',
        then: function (): void {
            foreach (glob(__DIR__.'/../routes/api/v1/*.php') ?: [] as $file) {
                Route::middleware('api')
                    ->prefix('api/v1')
                    ->name('api.v1.')
                    ->group($file);
            }
        },

    ->withMiddleware(function (Middleware $middleware): void {

<?php

declare(strict_types=1);

namespace App\Actions\Auth;

use App\Models\User;
use Illuminate\Support\Facades\Hash;
use Illuminate\Validation\ValidationException;
use Laravel\Sanctum\NewAccessToken;

final class IssueApiToken
{
    public function handle(string $email, string $password, string $deviceName): NewAccessToken
    {
        $user = User::query()->where('email', $email)->first();

        if ($user === null || ! Hash::check($password, $user->password)) {
            throw ValidationException::withMessages(['email' => __('auth.failed')]);
        }

        // Abilities mirror the permission names (TD-010) so a token never claims more than its user holds;
        // Policies remain the authorization decision point.
        $abilities = $user->getAllPermissions()->pluck('name')->values()->all();

        return $user->createToken($deviceName, $abilities);
    }
}
