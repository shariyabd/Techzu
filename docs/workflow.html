Agent-driven workflow

Six plans, executed one after another on main. Inside each plan, independent subtasks run in parallel as subagents. The gate and the reviews run once per plan, and nothing is committed until the owner approves.

Lifecycle of one plan

Waves

Parallel implementers write tests first and run only their own test files, each on techzu_testing_agent<N>. No git, no build, no full suite.

Gate, once

pint --test, phpstan, pest --parallel, and the frontend build, check and vue-tsc when the plan touched frontend code.

Review in parallel

Spec reviewer, quality reviewer, and security and test reviewer (opus), plus a documenter for docs/FEATURES.md (sonnet).

Fix

Implementers fix the confirmed findings, then only the affected tests, pint and phpstan run again.

Browser check

Playwright MCP against php artisan serve --port=8010, only for plans that change UI.

Report and wait

Features, results and limitations, plus each subtask's files and proposed commit message. The owner approves.

Commit per subtask

The session stages each subtask's files and creates one Conventional Commit for each. The owner pushes main.

Commit anatomy

feat(assignment): claim unassigned tickets under a row lock

Two agents claiming the same ticket at once: the second sees the
locked row as already assigned and gets TicketAlreadyClaimed.

The subject never starts with a plan number, and commits carry no co-author or AI attribution.
