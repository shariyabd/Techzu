## Document authority

When documents disagree, this is the order of authority:

1. **The code and its tests.** Every statement in these documents must be true of the current code. If a document is wrong, the document is fixed.
2. **[04 · Business logic](04-business-logic.md)** is the single source for *what the system does*. Other documents summarise it and link to it.
3. **[11 · Technical decisions](11-technical-decisions.md)** is the single source for *why*. A decision changes by amendment or by a new, superseding TD; numbers are never reused.
4. **[01 · Requirements](01-requirements.md)** is the brief and does not change. [02](02-product-requirements.md) records how we interpreted it.
5. Reference documents (03, 05–10, 12, 13) describe structure and operations and must stay consistent with 04 and 11.

The archived plans in `archive/plans/` have no authority over the current system.
